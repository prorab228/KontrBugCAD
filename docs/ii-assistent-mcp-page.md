# ИИ-Ассистент в КонтрCAD: инструкция по подключению (MCP)

КонтрCAD начиная с версии **0.9.80** поддерживает **Model Context Protocol (MCP)** — открытый стандарт, который позволяет нейросетям (DeepSeek, Claude, ChatGPT, Cursor и другим) напрямую управлять вашей 3D-моделью.

Вы просто пишете в чат: _«Создай корпус для Raspberry Pi 4»_ — и ассистент строит его через историю операций: создаёт примитивы, эскизы, выдавливания, булевы операции и фаски. Всё это остаётся обычными параметрическими операциями, которые можно отменить (Ctrl+Z) или поправить в панели истории.

Ниже — настройка для **веб-версии** и **десктопного приложения**, список инструментов и решение типовых проблем.

---

## Что выбрать: веб или десктоп

| Способ | Веб-версия | Десктопная версия |
|---|---|---|
| Транспорт | WebMCP (встроенный в браузер) | Streamable HTTP (локальный сервер) |
| Что нужно | Chrome 126+ / Edge и расширение-клиент | Установленный КонтрCAD Desktop + любой MCP-клиент |
| Где живут инструменты | в открытой вкладке редактора | в приложении, пока оно запущено |
| Доступно сразу | 16 инструментов (ядро), остальные — по группам | все 68 инструментов |

Если работаете в браузере — берите первый вариант. Если нужен «полный» ассистент в Cursor/Claude Desktop/DeepSeek Harness — второй.

---

## Настройка для веб-версии

Веб-версия использует **WebMCP**: редактор регистрирует свои инструменты в браузере, и ассистент «видит» открытую вкладку и управляет ей напрямую.

### Что понадобится

1. Браузер **Google Chrome** (версия 126 или новее) либо **Microsoft Edge**.
2. Клиент с поддержкой WebMCP — например, официальное расширение **DeepSeek Harness** (подойдёт и другой WebMCP-клиент).

### Пошаговая настройка

1. **Установите расширение-клиент** (для DeepSeek Harness — из Chrome Web Store).
2. **Настройте клиент**: в настройках расширения укажите адрес локального сервера, например `http://127.0.0.1:3080`, если запускаете DSH локально. Обычно Harness сам предлагает команду для терминала, которая всё настроит.
3. **Откройте редактор** в браузере: `kontrcad.ru/editor` или `dev.kontrcad.ru`.
4. **Начните диалог**: откройте боковую панель расширения поверх редактора. Ассистент подхватит инструменты автоматически.

> Если инструменты не появились после обновления редактора — перезагрузите вкладку с `?nocache=1` (или сбросьте кэш кнопкой в редакторе): редактор кэшируется service worker'ом.

### Важно: группы инструментов

В веб-версии **по умолчанию активны только 13 инструментов ядра + 3 мета-инструмента** (16). Остальные — в группах, чтобы не забивать контекст модели:

| Группа | Что внутри |
|---|---|
| `core` | чтение сцены, примитивы, трансформации, булевы операции *(активна всегда)* |
| `history` | undo/redo/jump, изменение параметров, описания операций |
| `sketches` | плоскости, эскизы, текст, DOF-анализ, extrude/revolve/sweep/loft |
| `images` | скриншот вьюпорта и рендер по ракурсам |
| `library` | встроенная библиотека моделей |
| `files` | проекты в локальной БД, экспорт STL/STEP/3MF/OBJ/PLY/GLTF |
| `advanced` | фаски, резьба, шестерни, массивы, группы, repair, decimate |

Ассистент открывает нужную группу сам:

```
list_tool_groups()                                    → какие группы есть и что активно
enable_tool_group({ groups: ["sketches", "advanced"] })  → включить
```

`enable_tool_group` в десктопной версии просто отвечает «все инструменты доступны сразу» — там группы не нужны.

### Промт для веб-версии

Скопируйте в чат ассистента:

```
Ты — инженер-ассистент в параметрическом CAD КонтрCAD (веб-версия, WebMCP).

КАНАЛ: только mcp__chrome__evaluate → window.__kc.call(name, args).
 • Возвращает объект/JSON — работай с данными, не пересказывай их целиком.
 • Нет __kc → перезагрузи вкладку с ?nocache=1.
 • Рендер: get_multi_view(size=512…1024). Картинка появляется в #kc-render-canvas — снимай её
   screenshot'ом по селектору; base64 в контекст не тяни. show:true — показать карточку пользователю.

ГРУППЫ: по умолчанию активны только core (16 инструментов с мета).
 • Нужного инструмента нет в списке → list_tool_groups() → enable_tool_group({groups:[...]}).
 • sketches — эскизы/текст/DOF/профильные операции; advanced — фаски, резьба, массивы;
   images — превью; files — проекты и экспорт; library — библиотека; history — история.
 • Справка по теме: get_help({topic}) — вызывай вместо перебора инструментов.

ДИСЦИПЛИНА:
 • get_scene_state — один раз в начале, дальше работай по известным UUID.
 • list_objects дешевле get_scene_state; get_object — для одного объекта.
 • Не перепроверяй успешные операции и не вызывай get_scene_state после каждого шага.
 • Несколько последовательных шагов → batch({steps:[...], rollback:true}).
 • get_multi_view — только в финале. Новая задача — новый чат.

ИСТОРИЯ:
 • update_operation сливает параметры (передавай только изменения).
 • undo/redo/jump_to требуют expected_current_id.

СТИЛЬ: кратко, прогресс галочками (✅ шаг N: …), финал — 3–5 предложений + превью.
Не объясняй очевидное.
```

### Проверка

Отправьте: _«Создай куб 40×40×40, вычти цилиндр Ø24 высотой 60 и покажи результат через get_model_preview»_. Если через 10–15 секунд появилась деталь с отверстием — всё работает.

## Настройка для десктопной версии (Electron + Streamable HTTP)

Десктопная версия не зависит от браузерных расширений и **не требует Chrome**. При обычном запуске КонтрCAD Desktop поднимает локальный MCP-сервер:

```
http://127.0.0.1:3100/mcp
```

Транспорт — **Streamable HTTP**, рекомендованный для актуальных MCP-клиентов (DeepSeek Harness, Cursor, Claude Desktop).

> ⚠️ Сервер доступен только пока запущено приложение «КонтрCAD». Закрыли редактор — соединение оборвалось.
> Сервер слушает только `127.0.0.1` и не требует авторизации, поэтому не пробрасывайте порт наружу.

### Способ 1 — одна команда (рекомендуется)

Harness подключает внешние MCP-серверы встроенным плагином `@deepseek-ai/dsh-mcp-client` — он уже входит в поставку, устанавливать ничего не нужно. Нужно только дописать абзац в конфиг профиля, это делает одна команда.

Откройте **PowerShell** и вставьте целиком:

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\web\cordis.patch.yml"
New-Item -ItemType Directory -Force (Split-Path $p) | Out-Null
if (-not (Select-String -Path $p -Pattern 'mcp-kontrcad' -Quiet -ErrorAction SilentlyContinue)) {
@"

- id: mcp-kontrcad
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: kontrcad
    transport: streamable-http
    url: http://127.0.0.1:3100/mcp
"@ | Add-Content -Path $p
}
```

Перезапустите `dsh web` — при следующем запуске в чате появятся инструменты `mcp__kontrcad__*` (68 штук).

Что важно:

- профиль `web` — для браузерного `dsh web`; для приложения **DeepSeek Harness Desktop** замените в пути `web` на `desktop`;
- если сервер уже был добавлен через **MCP Center**, сначала удалите его там (**Settings → MCP Center → Remove**): два клиента с одним именем `kontrcad` конфликтуют, и второй не загрузится;
- команда идемпотентна: повторный запуск ничего не дублирует.

### Способ 2 — вручную (macOS / Linux или без PowerShell)

Откройте `~/.dsh/profiles/web/cordis.patch.yml` (в Windows — `%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml`) и добавьте в конец файла:

```yaml
- id: mcp-kontrcad
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: kontrcad
    transport: streamable-http
    url: http://127.0.0.1:3100/mcp
```

Перезапустите `dsh web`: плагин подключится, вызовет `tools/list` и зарегистрирует все 68 инструментов.

### Способ 3 — через MCP Center (быстро, но без картинок)

Плагин `dsh-mcp-center` добавляет в Harness отдельную страницу управления MCP-серверами. Установите его один раз:

```bash
dsh plugin --profile web add dsh-mcp-center
```

1. Перезапустите `dsh web` и откройте **Settings → MCP Center**.
2. Нажмите **＋ Add MCP server** и заполните:
   - **Name**: `kontrcad` (станет префиксом инструментов: `mcp__kontrcad__*`)
   - **Type**: `Streamable HTTP`
   - **URL**: `http://127.0.0.1:3100/mcp`
   - **Auth Mode**: `none` (сервер локальный, токен не нужен)
3. Нажмите **Save**. Рядом с сервером появится статус **Connected (68 tools)**.

> ⚠️ **MCP Center передаёт ассистенту только текстовые блоки** и молча выбрасывает изображения —
> рендеры (`get_multi_view` и др.) до модели не дойдут. В десктопе PNG всё равно сохраняется
> в `%APPDATA%\kontrbugcad\renders` (или в запасной папке), и путь приходит в ответе, так что рендер можно открыть файлом.
> Если нужен именно vision — используйте **Способ 1** или **Способ 2**.

### Способ 4 — STDIO (Claude Desktop и подобные)

Клиенты вроде Claude Desktop умеют сами запускать сторонние программы. КонтрCAD стартует в скрытом режиме, отдаёт инструменты и завершается при отключении клиента.

```json
{
  "mcpServers": {
    "kontrcad": {
      "command": "C:\\Путь\\К\\Установленному\\КонтрCAD.exe",
      "args": ["--mcp"]
    }
  }
}
```

При запуске из исходников команда — `npm`, аргументы — `["start", "--", "--mcp"]`. После сохранения конфига перезапустите клиент.

### Проверка подключения

Спросите ассистента: «вызови `get_scene_state`». Если вернулся JSON со сценой (пусть и пустой) — сервер подключён, видны все 68 инструментов.

Если инструментов нет:

- КонтрCAD не запущен — порт `3100` не отвечает;
- сервер остался в MCP Center — уберите его оттуда (конфликт имён);
- правился не тот профиль (`web` или `desktop`);
- `dsh web` не перезапускали после правки конфига.

### Промт для ассистента (десктопная версия)

```

ВОЗМОЖНОСТИ: доступны все 68 инструментов — чтение сцены, примитивы, эскизы и текст,

ДИСЦИПЛИНА:
```

## Какие инструменты доступны ИИ

ИИ работает не с пикселями, а с **параметрическим ядром**: он создаёт настоящие операции, которые можно отменить (Ctrl+Z) или изменить параметры. Всего — **68 инструментов** (65 в группах + 3 мета-инструмента).

### Ядро и чтение сцены (`core`, активна всегда)

- `get_scene_state(include_objects?, include_operations?)` — полное состояние: объекты (UUID, имена, типы, позиции, размеры) и история операций.
- `list_objects()` — краткий список объектов. Дешевле, чем `get_scene_state`.
- `get_object(uuid)` — подробно про один объект: `bbox`, `size`, `position`, `position_bottom` (центр нижней грани).
- `body_topology(uuid, mode: "cylinders")` — найденные цилиндрические поверхности тела (валы/отверстия: тип, диаметр, глубина, ось).
- `create_primitive(type, …)` — 18 типов: куб, сфера, цилиндр, конус, тор, пирамида, шестигранник, труба, полусфера, звезда, сердце, клин, крыши и др.
- `move_object` / `rotate_object` / `scale_object` — трансформации. `move_object` поддерживает `position_mode: preserve | bottom | center`.
- `boolean_union` / `boolean_subtract` / `boolean_intersect` — булевы операции на Manifold (watertight-результат).
- `delete_objects(uuids)` — удаление (каскадно для групп).
- `batch(steps, rollback: true)` — несколько инструментов одним вызовом с откатом при ошибке.

### История операций (`history`)

- `undo(expected_current_id)` / `redo(expected_current_id)` / `jump_to(target_index, expected_current_id)` — навигация по истории с защитой от гонки.
- `update_operation(operation_id, new_params)` — изменить параметры операции; зависимые операции перестраиваются автоматически.
- `update_object_parameter(uuid, param_name, value)` — упрощённо: один параметр по UUID объекта.
- `remove_operation(operation_id)` — удалить операцию (откажется, если на неё ссылаются).
- `describe_operation(operation_id | object_uuid, description)` — подписать операцию для туториала/истории.

**Зачем `expected_current_id`:** пользователь может в любой момент нажать Ctrl+Z или добавить операцию руками. С проверкой ассистент получит ошибку и пересинхронизируется, без неё — сломал бы сцену. Это «оптимистичная блокировка».

### Эскизы, текст и профильные операции (`sketches`)

- `create_workplane(face_ref | position+normal, name, plane_type)` — плоскость эскиза (ассоциативно к грани или снапшотом).
- `add_sketch_entities(plane_id, entities, auto_constraints?, constraint_threshold?)` — линии, окружности, дуги, овалы, полилинии, сплайны, точки; у каждой сущности можно задать `pinned`. Новые элементы автоматически прогоняются через **авторастановку ограничений** (coincident в местах совпадений, horizontal/vertical, point_on_line, point_on_curve); отключается `auto_constraints: false`.
- `remove_sketch_entities` / `update_sketch_entity` — правка и удаление элементов (в т.ч. `pinned`).
- **`add_sketch_constraints(plane_id, constraints[], solve?, check_conflicts?)`** — ПАЧКА ограничений за один шаг истории: общая проверка конфликтов/дублей и один solve. Одиночный вариант — `add_sketch_constraint`; удаление — `remove_sketch_constraint`. Типы: horizontal, vertical, parallel, perpendicular, angle, equality, coincident, point_on_line, point_on_curve, point_line_distance, tangent, distance и др.
- **`pinned` вместо `fixed`**: положение элемента фиксируется закреплением (`pinned: true`), а не ограничением фиксации — так DOF и история остаются чистыми.
- **`add_sketch_text(plane_id, text, position, height, font_name, anchor, direction, pinned)`** — текст в эскизе: глифы превращаются в замкнутые полилинии. По умолчанию текст **закреплён** (`pinned: true`), поэтому не увеличивает DOF.
- `get_sketch_state(plane_id)` — элементы, регионы (готовые профили для выдавливания), ограничения.
- **`get_sketch_dof(plane_id?, tolerance?, include_entities?)`** — анализ степеней свободы: зафиксирован ли чертёж, сколько степеней осталось, есть ли конфликт или избыточные связи, какие элементы ещё подвижны.
- `extrude` — выдавливание профиля (`figures` или `selected_regions_data`) с наклоном, скруткой и масштабированием; `operation_type: new | cut | join`. Режим `extent_mode: "up_to_object"` + `up_to_uuid` выдавливает до выбранного тела: высота считается автоматически, а торец обрезается по его поверхности (плоской, наклонной или кривой).
- **Тип операции** определяется автоматически по реальному пересечению построенного тела с объектами сцены, если `operation_type` не задан (касание в пределах gap тоже считается). Нет пересечений → `new`. Для `extrude` при пересечении тип задаёт направление: `positive` → `join`, `negative` → `cut`, `both` → `join`. Для `revolve` / `sweep` / `loft` — доля объёма нового тела внутри существующего (> 50% → `cut`, иначе `join`). Если `target_uuids` не заданы, цели булевой операции тоже подбираются по пересечению.
- `revolve` — тело вращения (ось или `line_axis_points`). `pitch` — осевое смещение за оборот (мм): винтовое вращение для резьб и пружин, при `pitch ≠ 0` угол можно задавать до 3600°. Вращение всегда начинается от плоскости эскиза, `positive` — правый винт вокруг оси.
- `sweep` — профиль по траектории (`path_points`).
- `loft` — плавное соединение 2+ сечений.

### Изображения (`images`)

Рендер сделан под ассистента: одна картинка вместо четырёх, камера вписывает деталь в кадр целиком
(а не по описанной сфере), размер задаётся явно, а в ответе честно указана цена в vision-токенах —
картинка стоит их на каждом ходу, пока лежит в истории диалога.

- `get_viewport_screenshot(max_size?, hide_helpers?, show?)` — «что видит пользователь», по умолчанию 768 px по длинной стороне.
- `get_model_preview(uuids?, view?, size?, wireframe?, background?, show?)` — один ракурс, по умолчанию 768 px.
- `get_multi_view(uuids?, views?, size?, layout?, wireframe?, show?)` — мозаика ракурсов ОДНИМ изображением:
  по умолчанию `front | right | top | iso`, `size: 768` → 4 вида по 384 px.

Цена одной картинки (vision-токены у DeepSeek-маршрутов):

| Сторона картинки | Мозаика 2×2 | Один ракурс |
|---|---|---|
| 512 | ~184 | ~184 |
| 768 | ~382 | ~382 |
| 1024 | ~652 | ~652 |

- `views` — любой набор до 6 ракурсов (`iso`, `iso_alt`, `front`, `back`, `left`, `right`, `top`, `bottom`);
  чем меньше видов, тем крупнее каждый.
- `layout: "separate"` — каждый ракурс отдельной картинкой (в N раз дороже, зато детальнее).
- `show: true` — показать рендер в карточке прямо в редакторе.
- `max_size` — устаревший алиас `size`.

Как картинка доходит до модели:

- **десктопный MCP** — штатными image-блоками в ответе инструмента (клиенту нужен vision);
- **десктопный MCP, клиент без vision** — приложение дополнительно сохраняет PNG
  в `%APPDATA%\kontrbugcad\renders` (последние 40 файлов; если папка недоступна — во временную
  или в папку приложения) и дописывает пути в ответ,
  так что рендер можно открыть файлом;
- **веб-версия** — карточка `#kc-render-canvas` в редакторе: ассистент снимает её скриншотом элемента
  и получает ровно те пиксели, что отрендерил. base64 в контекст не отдаётся — это дорого
  (`__kc.call(name, args, { inline: true })` — если он всё-таки нужен).

**Нужен vision в MCP-клиенте.** Если клиент изображения не показывает, рендер всё равно останется
в карточке редактора — пользователь увидит его сам.

### Библиотека (`library`)

- `list_library_items(category_id?, search?, limit?)` — каталог встроенной библиотеки (без параметров — категории). Вызывайте до импорта.
- `import_library_model(item_id | name_query, position?, color?)` — вставить модель из библиотеки.

### Проекты и экспорт (`files`)

- `new_project(confirm: true)` — очистить сцену и начать с нуля.
- `save_project(name, description?, existing_key?, overwrite?)` — сохранить в локальную БД.
- `list_saved_projects(search?, limit?)` / `open_saved_project(key, confirm: true)` / `delete_saved_project(key, confirm: true)`.
- `export_project_file(compact?)` — скачать `.kbcad` для бэкапа или переноса.
- `export_model(format: stl | stl-ascii | obj | ply | gltf | 3mf | step, file_name?, selected_only?)`.

**Импорт проекта из файла** остаётся за пользователем — ассистент не может открыть диалог выбора файла.

### Продвинутое (`advanced`)

- `fillet_chamfer(target_uuid, edges, distance1, distance2?, segments?)` — фаска/скругление по рёбрам. Перед вызовом получите рёбра: `get_object_edges`.
- `get_object_edges(uuid, axis?, min_length?, min_crease_angle?, near_point?, radius?, limit?)` — рёбра в мировых координатах.
- `get_object_faces(uuid, axis?, min_area?, near_point?, radius?, limit?, include_face_ref?)` — грани (в т.ч. `face_ref` для создания плоскости по грани).
- `thickness(uuid, thickness, mode?, segments?, inset?)` — оболочка заданной толщины.
- `create_thread(type, standard?, diameter, pitch, length, threadType, …)` — отдельное тело резьбы.
- `thread_cut(target_uuid, diameter, pitch, length, position, …)` — нарезать резьбу на существующем теле (внутреннюю/наружную).
- `create_gear(teeth, module, faceWidth, …)` — эвольвентная шестерня.
- `split_by_plane(uuid, plane_id)` — разрезать плоскостью.
- `repair_geometry(uuids, …)` — починить «грязный» STL (manifold).
- `decimate_mesh(uuids, reduction_factor?, …)` — уменьшить число полигонов.
- `create_text3d(text, font_size?, depth?, …)` — объёмный текст.
- `array_linear` / `array_circular` — массивы.
- `mirror_object`, `duplicate_object`, `group_objects`, `ungroup_objects`.
- `change_color`, `change_name`, `change_visibility`.

### Мета-инструменты (доступны всегда)

- **`list_tool_groups(include_tools?)`** — какие группы есть, что активно, сколько инструментов.
- **`enable_tool_group(groups)`** — включить группы (в вебе; в десктопе всё уже доступно).
- **`get_help(topic)`** — подробная справка по теме вместо длинных описаний в схеме: `general`, `sketch`, `extrude`, `move_object`, `boolean_operations`, `fillet_chamfer`, `get_object_edges`, `repair_geometry`, `create_primitive`.

### Как экономить контекст

- `get_help(topic)` — длинные инструкции не висят в схеме инструментов, их запрашивают по необходимости.
- `batch` — несколько последовательных шагов одним вызовом (с `rollback: true` при ошибке сцена откатится).
- `expect` — во многих инструментах (`create_primitive`, `move_object`, булевы, `extrude`, `fillet_chamfer`) можно передать ожидаемые `bbox`/`volume`: ассистент сразу узнает, что размер не сошёлся, без отдельной проверки.
- `list_objects` вместо `get_scene_state`, `get_object` для одного объекта, изображения — только для финального показа.
- Изображения: мозаика из 4 видов в одной картинке дешевле четырёх отдельных, а `size: 512`
  (~184 токена) достаточно, чтобы проверить «на месте ли отверстие/фаска». `size: 768` (~382) —
  компромисс, `1024` (~652) — когда нужны мелкие детали. Каждый рендер платится на всех
  последующих ходах, пока картинка в истории.

## Примеры промптов

**Простой:**

> Создай куб 50×50×50 мм, затем цилиндр радиусом 10 мм и высотой 60 мм. Вычти цилиндр из куба — получится сквозное отверстие.

**Корпус:**

> Создай корпус: куб 100×80×50 мм. Сделай оболочку (`thickness`) с толщиной стенок 2 мм. Затем 4 цилиндра радиусом 3 мм на расстоянии 10 мм от углов и вычти их из корпуса. В конце — фаска 1 мм на верхних рёбрах.

**Эскиз с текстом и проверкой DOF:**

> На верхней грани корпуса создай плоскость эскиза. Нарисуй прямоугольник 40×15 и добавь текст «КонтрCAD» высотой 6 мм по центру. Проверь `get_sketch_dof` — текст должен быть закреплён. Выдави прямоугольник на 2 мм и вырежи текст на 0.5 мм.

**Резьба:**

> На валу Ø20 нарежь внешнюю резьбу M20×2.5 длиной 15 мм. `position` подбери так, чтобы витки начинались в 3 мм от основания вала. Покажи результат через `get_multi_view`.

## Ограничения и безопасность

- **Локальность.** Десктопный сервер слушает только `127.0.0.1:3100`, авторизации нет — не публикуйте порт в сеть.
- **Жизненный цикл.** HTTP-сервер живёт, пока запущен КонтрCAD; STDIO-режим завершается вместе с клиентом.
- **Необратимое — только вручную.** Сжатие/очистка истории, импорт файла проекта и выбор файлов остаются за пользователем.
- **История защищена.** `undo/redo/jump_to` требуют `expected_current_id` — ассистент не «перескочит» через ваши правки.
- **Группы.** В веб-версии набор инструментов ограничен активными группами — это не баг, а экономия контекста.

## Решение проблем

| Симптом | Что делать |
|---|---|
| Ассистент пишет «инструмент не найден» | В вебе включите группу: `list_tool_groups()` → `enable_tool_group({groups:[...]})` |
| Ошибки с UUID «объект не найден» | Попросите `get_scene_state` или `list_objects` — ассистент увидит актуальные UUID |
| Нет `window.__kc` в веб-версии | Перезагрузите вкладку с `?nocache=1` (или сбросьте кэш в редакторе) |
| Ассистент ищет КОМПАС-3D или другие программы | Уточните: «Ты работаешь внутри редактора КонтрCAD. Используй только свои MCP-инструменты» |
| В десктопе не подключается `http://127.0.0.1:3100/mcp` | Проверьте, что КонтрCAD запущен; не занят ли порт 3100 другой программой; в консоли приложения должно быть `[MCP] Streamable HTTP server: http://localhost:3100/mcp` |
| В MCP Center статус не `Connected` | Проверьте тип транспорта (`Streamable HTTP`, не SSE) и URL с `/mcp` на конце |
| Инструменты есть, но модель «не видит» изображения | Включите группу `images` и убедитесь, что у клиента есть vision |
| В DSH (MCP Center) рендер приходит текстом без картинки | MCP Center пробрасывает только текстовые блоки. В десктопе PNG сохраняется в `%APPDATA%\kontrbugcad\renders` (или в запасной папке), путь есть в ответе — откройте файл; либо подключите сервер через `@deepseek-ai/dsh-mcp-client`, он картинки передаёт |
| В вебе рендер не появился | Рендер показывается в карточке `#kc-render-canvas` в редакторе; если клиент не умеет image-блоки — снимайте карточку скриншотом по этому селектору |

## Обновления этой инструкции

- **Рендер переделан под ассистента:** `get_multi_view` получил `views` (до 6 ракурсов), `size`
  (256…1536, по умолчанию 768), `layout: mosaic | separate` и `show`; камера вписывает деталь в кадр
  целиком; в ответе пишется цена в vision-токенах. В вебе вместо новых вкладок — карточка
  `#kc-render-canvas` в редакторе (её и снимает ассистент), base64 в контекст не отдаётся.
  В десктопе PNG рендера дополнительно сохраняется в `%APPDATA%\kontrbugcad\renders` (запасные папки: temp, папка приложения) — путь
  дописывается в ответ, поэтому рендер доступен даже клиентам без vision (MCP Center и т.п.).
- **68 инструментов** вместо 63: добавлены `batch`, `body_topology`, `get_object_edges`, `get_object_faces`, `describe_operation`, `add_sketch_text`, `get_sketch_dof`, `list_tool_groups`, `enable_tool_group`, `get_help`.
- Описаны **группы инструментов**: в веб-версии по умолчанию активны только `core` + мета (16), остальные включаются `enable_tool_group`.
- Добавлены разделы про **текст в эскизе** (с закреплением, чтобы не поднимать DOF) и **DOF-анализ**.
- Актуализирован десктопный транспорт: **Streamable HTTP** (`http://127.0.0.1:3100/mcp`), убран устаревший WebSocket из решения проблем.
- Полный промт для десктопной версии (раньше он был обрезан).
- Уточнены параметры инструментов и советы по экономии контекста (`get_help`, `batch`, `expect`, `get_multi_view` только в финале).
